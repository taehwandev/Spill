# Detailed PRD: Unsigned Install Bypass

## PRD Authoring Gate

`00-intake.md` has `Decision: build` and `Clarity: clear`.

## Summary

Add a command-based install path for current ad-hoc signed Spill releases. The
command should download the latest ZIP release, install `Spill.app` into
Applications, remove the macOS quarantine attribute that causes the Trash prompt,
and open the app.

## Resolved Inputs

- maintainer decisions: provide a command-based bypass for the Trash prompt.
- repo-researched facts: release assets provide stable `Spill-macos.zip`; the
  download site is served from `docs/` via GitHub Pages.
- assumptions: hosting the installer script from the Pages site is acceptable for
  the current direct distribution path.

## Goals

- Give users a single terminal command that makes the current release usable.
- Explain why the command is needed for ad-hoc signed builds.
- Keep the normal DMG and ZIP download links available.
- Preserve the Developer ID notarization path as the long-term fix.

## Non-goals

- Notarize the current release without Apple credentials.
- Add runtime app behavior or new app permissions.
- Replace the release workflow.

## User Stories

- As a tester, I want one command that installs Spill when macOS blocks the
  downloaded app as damaged.
- As a maintainer, I want the release page and site to explain the unsigned build
  state honestly.

## UX Requirements

### Entry Point

The command appears in the install section of the download site and in README.
Future release notes should include the same command.

### Layout

The site keeps primary DMG/ZIP buttons and adds a compact terminal command block
in the install section.

### States

- loading: installer prints download, extraction, installation, and completion
  messages.
- empty: not applicable.
- unavailable: installer exits if `Spill.app` is not present in the ZIP.
- permission required: installer uses `sudo` when `/Applications` is not writable.
- success: Spill is installed and opened.
- failure: shell exits non-zero with the failing command or explicit archive
  error.

## Functional Requirements

1. Host an installer script at `docs/install.sh`.
2. The script must download the stable latest ZIP release by default.
3. The script must support test overrides for download URL, install directory,
   and opening behavior.
4. The script must remove `com.apple.quarantine` from the installed app.
5. The site and README must show the hosted install command.
6. Release notes generated by CI must include the same unsigned install guidance.

## Behavior Scenarios

### Terminal Install

Given a user trusts the current Spill release
When they run the hosted install command
Then the latest ZIP is installed to Applications, quarantine is removed, and Spill
opens.

### Already Installed

Given a user already copied Spill into Applications
When they run the documented `xattr` command
Then the quarantine flag is removed and macOS no longer shows the Trash prompt for
that copy.

### Archive Failure

Given the latest ZIP cannot be downloaded or does not contain `Spill.app`
When the installer runs
Then the installer exits non-zero and does not claim success.

## Acceptance Criteria

- `docs/install.sh` passes shell syntax validation.
- The installer works against a local ZIP with a temporary install directory.
- The site exposes the command without hiding DMG/ZIP links.
- README and release note generation mention ad-hoc signing and the quarantine
  command.

## Metrics

- perceived latency: terminal progress is visible during download.
- reliability: install path uses stable latest ZIP asset.
- resource use: no app runtime impact.

## Rollout

- MVP: hosted install script, site docs, README, release note template.
- later: remove bypass emphasis once Developer ID signing and notarization are
  configured.
